# OYWW1000 腕带 SDK 测试用例

> 本文件针对 **OYWW1000 腕带** 从《测试计划.md》逐条展开为可执行用例。
> 每个用例标注：测试目的、测试流程与逻辑、有效性说明、是否可自动化、人工介入（半自动/人工）。
> 用例 ID 沿用《测试计划.md》的 ID（`CTRL-*`/`DEV-SM-*`/`DATA-*`/`PARAM-*`/`MULTI-*`/`BIN-*`/`BATT-*`/`LOG-*`/`HW-MAN-*`），便于追溯。

---

## 0. 设备信息与能力假设

| 项 | 内容 |
|----|------|
| 设备型号 | OYWW1000（腕带） |
| 广播名前缀 | `OYWW`（兼容用 `OY` 前缀匹配） |
| 类型归属 | OYM 命名设备 / 传统 OYMotion 设备（非“新 EMG 设备”） |
| SDK 版本 | 0.8.0 |

**能力假设（连接后必须用 `getDeviceInfo()` 实际确认）**

| 能力 | 判定字段（DeviceInfo） | 假设 | 状态 |
|------|------------------------|------|------|
| 肌电 EMG | `EmgChannelCount > 0` | 支持 | 适用 |
| 手势 GEST | 无直接字段，起流后看 `NTF_GEST` 是否有数据 | 支持，且与 EMG 互斥 | 适用（待确认） |
| 加速度 ACC | `AccChannelCount > 0` | 支持 | 适用 |
| 陀螺仪 GYRO | `GyroChannelCount > 0` | 支持 | 适用 |
| 欧拉角 Euler | `EulerChannelCount > 0` | 支持 | 适用 |
| 四元数 Quat | `QuatChannelCount > 0` | 支持 | 适用 |
| 聚合 IMU（`NTF_IMU`） | `ImuChannelCount > 0` | 不支持（仅新 EMG 设备） | 待确认 |
| 磁角度 MAG_ANGLE | `MagAngleChannelCount > 0` | 腕带通常无 | 待确认 |
| 阻抗 IMPEDANCE | `ImpeChannelCount > 0` | 腕带通常无 | 待确认 |
| EEG/ECG/PPG/SpO2/BRTH | `Eeg*/Ecg*/Ppg*/Spo2*/Brth*ChannelCount > 0` | 腕带通常无 | 待确认 |

> 说明：上表“待确认”项**不省略**，进入实际编码/执行阶段时以 `getDeviceInfo()` 返回值为准：字段 `>0` 才执行对应数据流用例，否则记录“设备不支持，跳过”。

## 1. 环境与前置条件

- Python 3.10~3.14，`sensor-sdk==0.8.0`（`pip install --upgrade sensor-sdk`）。
- 蓝牙已开启（bleak 后端）或 dongle 已正确绑定（bumble 后端，`checkSetupDongle()` 返回 `OK`）。
- 设备已上电、在扫描范围内、广播名以 `OYWW` 开头。
- 每脚本结束调用 `SensorControllerInstance.terminate()`；Ctrl+C 异常路径也需 `terminate()`。
- 连接/起流/停流等操作之间留 ≥100ms 间隔。
- 设备 MAC、前缀写入独立 `config.py`（不硬编码）。

## 2. 控制器与扫描（SensorController）

### CTRL-FUNC-001 蓝牙未开启时 `isEnable==False`，`startScan` 被拒绝
- **测试目的**：验证控制器能感知蓝牙开关状态，并在蓝牙关闭时拒绝扫描。
- **前置条件**：主机关闭蓝牙（或禁用 BLE 后端）。
- **测试流程与逻辑**：
  1. 关闭蓝牙。
  2. 读取 `SensorControllerInstance.isEnable`。
  3. 调用 `startScan(3000)` / `scan(3000)`，观察返回值与 `isScanning`。
- **预期结果**：`isEnable==False`；`startScan`/`scan` 不进入扫描态（返回 False 或空列表），`isScanning==False`。
- **有效性说明**：若蓝牙关闭时仍能“成功扫描”，说明 SDK 未校验硬件使能，属功能缺陷。
- **是否可自动化**：semi-auto
- **人工介入**：人工关闭/开启蓝牙开关。

### CTRL-FUNC-002 蓝牙开启时 `isEnable==True`，`onEnableCallback` 触发
- **测试目的**：验证蓝牙使能状态与回调。
- **前置条件**：蓝牙可切换。
- **测试流程与逻辑**：注册 `onEnableCallback`；在运行中关闭再开启蓝牙，记录回调与 `isEnable` 变化。
- **预期结果**：开启时 `isEnable==True` 且回调收到开启事件；关闭时收到关闭事件。
- **有效性说明**：确认使能回调与状态一致，避免状态与真实硬件不同步。
- **是否可自动化**：semi-auto
- **人工介入**：人工切换蓝牙开关。

### CTRL-FUNC-003 `startScan(period_in_ms)` 成功返回 True，`isScanning` 翻转
- **测试目的**：验证周期扫描启动与状态翻转。
- **测试流程与逻辑**：`startScan(3000)` → 读返回值 → 读 `isScanning` → `stopScan()` → 再读 `isScanning`。
- **预期结果**：启动返回 True、`isScanning==True`；停止后 `isScanning==False`。
- **有效性说明**：状态机正确翻转是后续 `scan`/`requireSensor` 的前提。
- **是否可自动化**：auto
- **人工介入**：无

### CTRL-FUNC-004 `scan(period_in_ms)` / `asyncScan` 返回 `list[BLEDevice]`
- **测试目的**：验证单次扫描能发现 OYWW1000。
- **测试流程与逻辑**：调用 `scan(5000)`，遍历返回列表，检查是否有 `Name` 以 `OYWW` 开头、且含 `Address`/`RSSI` 的设备。
- **预期结果**：返回 `list[BLEDevice]`，包含至少一台 OYWW1000，`Name`/`Address`/`RSSI` 非空。
- **有效性说明**：能稳定发现设备是后续连接的前置，也验证后端（bleak/bumble）扫描链路。
- **是否可自动化**：auto
- **人工介入**：无（需设备已开机在范围内）

### CTRL-FUNC-005 `onDeviceFoundCallback` 周期触发
- **测试目的**：验证周期扫描回调按 `period_in_ms` 触发并返回未连接设备。
- **测试流程与逻辑**：注册 `onDeviceFoundCallback`，`startScan(3000)`，统计回调次数与是否含 OYWW1000。
- **预期结果**：约每 3s 触发一次，回调列表含 OYWW1000，且不重复推送已连接设备。
- **有效性说明**：确认回调节律与去重逻辑。
- **是否可自动化**：auto
- **人工介入**：无

### CTRL-FUNC-006 `stopScan()` 后回调停止
- **测试目的**：验证停止扫描后不再有发现回调。
- **测试流程与逻辑**：`startScan` → 观察回调 → `stopScan` → 等待 ≥2 个周期确认无新回调。
- **预期结果**：停止后无新回调，`isScanning==False`。
- **有效性说明**：防止扫描线程泄漏/后台持续工作。
- **是否可自动化**：auto
- **人工介入**：无

### CTRL-FUNC-007 `requireSensor` 有效/无效

## 3. 设备连接与状态机（SensorProfile）

> 下列用例均针对 OYWW1000 单台执行。

### DEV-SM-001 `connect()` 成功，状态迁移 Disconnected→Connecting→Connected→Ready
- **测试目的**：验证连接成功与状态迁移序列。
- **测试流程与逻辑**：注册 `onStateChanged`，`requireSensor` 后 `connect()`，记录每次状态变化。

- **有效性说明**：连接是全部后续操作前提；迁移顺序错误会导致指令在错误状态下发送。

## 10. 执行方式汇总

| 分类 | auto | semi-auto | manual | 备注 |
|------|:----:|:---------:|:------:|------|
| 控制器与扫描 | 多数 | 蓝牙开关、dongle 引导 | — | CTRL-FUNC-001/002/011 需人工 |
| 连接与状态机 | 多数 | 断连/断电恢复类 | — | DEV-SM-002/008/009/010/012 需人工 |
| 数据流 | 多数 | 手势/运动激发 | — | DATA-FUNC-005 视激发方式 |
| 参数 | 多数 | — | — | PARAM-FUNC-009 不适用 |
| 多设备同步 | 多数 | 后端切换 | — | 需 ≥2 台，否则跳过 |
| Bin | 多数 | 磁盘不足 | — | — |
| 电量/日志 | 多数 | 电量变化观察 | — | — |
| 人工硬件 | — | — | 全部 | HW-MAN-001/002/003 |

### 待确认项（执行前用 `getDeviceInfo()` 确认）
- 聚合 `NTF_IMU`（`ImuChannelCount`）——传统设备预计 0。
- `MAG_ANGLE` / `IMPEDANCE` / `EEG` / `ECG` / `PPG` / `SpO2` / `BRTH` 对应 `ChannelCount`。
- 上述字段 `>0` 才执行对应数据流/参数用例，否则记录“设备不支持，跳过”。

### 判定标准
- P0 用例 100% 通过；P1 ≥95%；P2 ≥90%。
- 失败保留 SDK 日志与 `.bin` 用于复现。
- 缺设备（如多设备同步需 ≥2 台）时整体“跳过”，不判失败。
